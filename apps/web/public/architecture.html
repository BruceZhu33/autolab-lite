04横切系统(贯穿所有阶段)

🔒 审批门

Plan 批准必须粘 spec_hash(内容哈希);Agent/MCP 面上无 approve——"Agent 不能自己批准"有测试断言兜底。循环内的自动批准单独标记 approved_by=iteration-loop 可审计。

🩹 补丁系统(唯一写通道)

每次写文件:备份 orig → 写 → py_compile → 失败回滚。会话、单发、debugger 全穿它;restore-code 可整体回滚到基线代码(创建过的文件删除)。

🧵 调度与队列

Scheduler 0.2s tick + SQLite 事务 GPU 租约;基线队列线程 5 秒 tick,单写者(HTTP 轮询只读)防重复起跑;runner 是服务器上的 nohup 独立进程——Mac 断网训练照跑,恢复后事件补传。

🗂 留痕即资产

EXP 实验文件 · failures.md(带 OOM 死因日志尾部)· 补丁目录(orig 可回滚)· 会话转录 transcript.jsonl · tokens 计量循环累计——失败也全留,不删。

🔌 MCP(23 工具)

stdio server,agent 视角的读写面(无 approve)。P4 补齐:probe_server / preview_plan / cancel_job / retry_job / get_run_results——与 Repo/会话工具同源。

🧪 质量底座

149 个测试全绿:seed 对齐、确认门、队列推进、会话回退、MCP 语义全有覆盖;DB 已到 v15(schema 迁移内置)。
