# 资产清单与迁移边界

## 1. 结论

旧工作区不是整体迁移源，而是资产库。迁移单位必须是经过分类的文件或概念，不能复制整个目录后继续删减。

## 2. A 类：规范性资产，可直接带入新工作区

### A1. 新协议

位置：`source-assets/contracts-v1/`

包含 `PlanSpecV1`、`ManifestV1`、`RunnerEventV1` 和 `ArtifactV1`。它们是新产品协议的规范来源，优先级高于所有旧 schema、Runner 和 Control 代码。实现可以生成语言类型，但不得为了兼容旧 `/attempts` 字段而修改协议语义。

### A2. 科研工作区模板

位置：`source-assets/research-protocol/`

包含 `.autolab/context.md`、实验记录和失败经验模板。可以复制为新仓库测试 fixture 或由 CLI 生成；运行状态不得写入这些文件。

### A3. 产品、架构和验收文档

本目录的 `00` 至 `09` 文档可复制到新仓库 `docs/reboot-source/`。编码 AI 必须优先读取 `06` 和 `08`，并受 `09` 中的里程碑决策门约束。

## 3. B 类：只作为实现参考，按新模型重写

### B1. 旧 GPU Runner

来源：`gpu-agent/autolab_agent/`、`gpu-agent/pyproject.toml`、`gpu-agent/uv.lock`

本交接包位置：`source-assets/gpu-agent/`

可以参考：

- dispatch_id 幂等与 payload hash 思路；
- 进程组、日志文件、事件序号和 execution deadline；
- 控制端离线后远端进程继续运行的边界。

禁止直接迁入，原因包括：

- 旧 `/attempts`、旧状态和旧 Manifest 与 v1 协议不兼容；
- Runner 内部维护一卡一队列，与 Control 持久 GPU Lease 的唯一调度权冲突；
- 空 Token 会退化为无鉴权，HMAC 也可能使用空密钥；
- 工作目录、输出目录、shell 命令和 symlink 没有满足新路径边界；
- 重启时仅凭持久化 PID 杀进程，存在 PID 复用风险；
- 状态更新和事件追加未形成统一的原子接口。

新 Runner 必须从 `contracts-v1/` 和测试出发实现；详细要求见 `source-assets/gpu-agent/REFERENCE_ONLY.md`。

### B2. Control 参考代码

这些文件已复制到 `source-assets/control-reference/`，用于查看经过真机验证的细节。它们依赖旧表、旧 tx 和旧状态机，不能直接成为新 Control 的生产模块。

| 资产 | 可复用知识 | 必须去掉的旧耦合 |
|---|---|---|
| `agent_client.py` | Runner HTTP 调用与错误分类 | 旧接口字段和超时常量 |
| `ssh/transport.py` | local/SSH 双传输、隧道、SFTP | 旧 server row 结构 |
| `ssh/keychain.py` | macOS Keychain/FileStore 抽象 | AutoLab 旧目录约定 |
| `manifest.py` | canonical JSON + HMAC | 旧大 Manifest 字段 |
| `security.py` | loopback capability token | 旧 FastAPI 装配 |
| `services/agent_deploy.py` | 离线 Runner 部署、版本探测 | 旧数据库查询和部署路径 |
| `services/dispatcher.py` | 幂等派发和失败重试思想 | outbox、attempt、Tx 状态机 |
| `services/monitor.py` | Runner 事件消费、对账、日志归档 | 旧 project/run/attempt 三层推进 |
| `services/env_setup.py` | conda/venv 探测和远端环境经验 | 协议冻结、data replica 和阶段迁移 |

推荐方式：为新接口先写测试，再从参考文件复制短小、无领域状态的函数。

## 4. B 类测试资产

本包 `source-assets/tests-reference/` 保存：

- `e2e_local.py`：真实 Control + Runner 双进程纵切。
- `e2e_stop_ws.py`：停止链、WebSocket 和幂等行为。

不能直接运行，因为它们调用旧 API；应把测试场景和进程装配方式迁入新测试，删除旧协议冻结、预算和三层状态断言。

旧 `e2e_m2_reliability.py` 含具体生产服务器、用户名、凭据路径和远端进程操作，因此没有复制进交接包。其“Control 重启、Runner 重启、断线对账、硬截止”场景已经提炼到新需求和验收清单中。

## 5. B 类协议资产

本包 `source-assets/contracts-reference/` 保存：

- `plan.schema.json`：查看旧计划曾记录哪些运行事实。
- `ws-events.md`：事件序号、断线恢复和快照语义参考。

新协议已经固定在 `source-assets/contracts-v1/`。旧 schema 只能帮助避免遗漏，不是兼容目标；冲突时以 contracts-v1 为准。

### B4. Any Science Framework：只吸收概念

参考：`https://github.com/feedy-hub/any-science-framework`（2026-09-17 评估）。

吸收进本产品的设计原则：

- 科研资产落到文件，不依赖聊天历史；
- 实验前明确 hypothesis、baseline、metrics 和 success criteria；
- 人类仍是 PI，Agent 产出必须经过用户批准；
- 结论必须引用证据；失败方向记录死因与重新考虑条件；
- UI 是科研资产和运行事实的投影，不另建事实源。

明确不迁移：

- `.claude/agents`、commands、hooks 和 Claude 专属权限配置；
- Scholar/Methodologist/Executor/Analyst/Reviewer 多角色编排；
- IDEA→DESIGN→APPROVED→RUNNING 等 Markdown 状态机；
- 本地 `nohup + PID` 执行器；
- 它的简易 UI 和大型 setup shell。

该仓库评估时未声明开源许可证，因此本包不复制其源码或模板；这里只记录独立提炼的产品原则。

### B5. GLM 官方接入资料

产品第一优先适配 GLM Coding Plan，但不复制或嵌入其客户端：

- 工具接入说明：`https://docs.bigmodel.cn/cn/guide/develop/others`
- MCP 与 Agent 实践：`https://docs.bigmodel.cn/cn/coding-plan/best-practice/mcp-and-agent`

官方资料表明 GLM Coding Plan 可通过受支持的编码 Agent 工具使用，并提供 Anthropic/OpenAI 兼容端点。AutoLab 选择更稳定的工具边界：模型端点和密钥由 Agent 宿主管理，AutoLab 只提供本地 MCP/CLI 工具。

不得在 AutoLab 源码中硬编码某个 GLM 模型编号、API Key、套餐端点或宿主配置。模型版本变化不应导致 Control/Runner 发布新版本。

## 6. L 类：许可决策前隔离的 UI 资产

### L1. Multica 源码快照和截图

来源：`frontend-next/`

本交接包位置：`source-assets/ui-reference/`

快照包含原始许可证、NOTICE 和 provenance，并排除了依赖与构建缓存。它用于证明旧设计来源和帮助做许可评估，不是默认可迁入的生产资产。

产品希望保留的是以下需求，而不是默认复制 Multica 代码：

- 高密度但清晰的 Sidebar、PageHeader 和 Dashboard shell；
- 横向实验任务板、紧凑卡片、状态/进度/指标表达；
- 项目工作区主从布局；
- GPU 服务器的显存、利用率、温度、磁盘和 Runner 状态卡片。

M5 前必须在“已授权迁移、内部保留品牌、独立实现”中选择一条，具体见 `07-Multica壳迁移清单.md` 和 `09-v1.3审查修订与决策门.md`。没有书面决策时，编码 AI 不得解压源码快照、复制组件或做像素级复刻。

截图也必须按用途标注：GPU Servers 截图只是加载态；Issue Detail 和 Phase 4 截图含评论流、Agent 对话和自动迭代等新产品非目标，只能用于观察密度和布局，不能作为功能清单。

### L2. Multica 来源品牌图标

位置：`source-assets/brand/`

这些文件来自 Multica，`icon.svg` 也明确标注 Multica。它们只作来源留档，许可决策前不得作为 AutoLab favicon、应用图标或商标。

## 7. C 类：留在旧工作区，不迁移

### C1. `frontend-next/` 的运行时架构

完整源码已作为参考快照保留，但以下运行时架构不迁移：

- 团队协作领域模型与单用户实验队列不匹配；
- 包含约 39 万行 TS/TSX 和大量无关 query/provider；
- 运行时依赖 fixture fetch 适配 Multica API；
- 一个事件会引发全局失效和多列重复读取。

只有 M5 许可决策允许时才可从 `views` 和 `ui` 移植视觉组件；任何路径都禁止为了让组件“原样运行”而连带恢复 `core`、IssueSurface 查询规划或全局 Provider。选择独立实现时不得阅读或复制快照源码。

### C2. `ui/`

不迁移源码。旧 UI 是历史纵切验证工具，与新 UI 并存只会恢复双前端。若某个表单字段确有价值，按需求重新实现。

### C3. 旧数据库与 migrations

不把 `sidecar/migrations/0001...` 复制到新工程。旧库可只读保留，用导出脚本迁移必要配置。

尤其不迁移：

- 49 表契约；
- project/run/attempt 合法迁移表；
- protocol/candidate/batch/ablation/test release；
- review/thread/proposal 工作流状态；
- 为不可变科研流程建立的 trigger。

### C4. `RD-Agent-main/`

P0 不迁移。新产品把 GLM 驱动的外部 Agent 作为首要规划者，不在 Control 中嵌入 RD-Agent。以后若真实训练证明需要无人值守自动修改引擎，再通过稳定工具接入。

### C5. 归档原型、营销站和完整截图集

`归档-antd原型/`、landing 页面素材和完整 `gui-test-screenshots/` 不迁移。它们不属于执行资产。

## 8. 运行数据迁移

旧默认数据目录位于 macOS：

```text
~/Library/Application Support/AutoLab
```

迁移必须分为“配置”“凭据”“历史”三类：

### 8.1 可导出的配置

- server 名称、host、port、username、transport mode；
- project 名称、server 对应关系、远端工作目录；
- conda/venv 配置；
- 默认训练命令、输出目录和指标规则；
- GPU 选择偏好。

导出为经过人工检查的 JSON，不能直接把旧 SQLite 复制到新工作区。

### 8.2 凭据

- SSH 私钥、密码、Runner token 和 HMAC key 不进入 Git 或普通 JSON。
- 新 Control 启动后重新关联系统钥匙串条目；无法关联时由用户重新输入。
- 文件式凭据只允许通过用户明确操作迁移，权限保持 0600。

### 8.3 历史记录与产物

- 旧数据库和 artifacts 目录整体只读归档。
- P0 不导入每条旧 state_event。
- 如需在新界面查看旧实验，只导出每个已完成 run 的摘要：项目、命令、代码锚、时间、结果、产物路径。
- 原始日志继续从旧归档打开，不复制成新 Job 事件。

## 9. UI 参考资产

`source-assets/ui-reference/` 保留许可受限的源码快照和少量截图，仅在完成 M5 许可决策后用于相应路径：

- 在已授权路径中移植 Sidebar、页面壳、看板列和卡片的视觉交互；
- 在独立实现路径中只提炼与来源无关的功能、信息层级和性能目标；
- 保留 GPU 服务器卡片中已经验证有用的遥测；
- 识别任务详情中哪些日志与结果信息有用；
- 保留资源消耗动作批准时的信息表达。

新界面继续满足用户喜欢的高密度科研看板体验，但是否使用 Multica 源码和品牌由许可决策决定。列状态始终由轻量 Plan/Job 数据派生；不沿用通用 Issue 查询系统和评论时间线数据模型。

## 10. 资产验收

交接包满足以下条件才可复制到新工作区：

- Runner 参考源码完整且无 `.venv`、日志、缓存或密钥，并明确标注 reference-only。
- Control 参考代码明确标注非 drop-in。
- 没有复制旧数据库、runtime.json、capability token 或 credentials。
- 没有复制 `frontend-next/node_modules`、`.next` 或旧 UI 构建产物。
- 每类资产都有保留理由和新工作区用途。
- Multica 源码和品牌资产有许可门，默认不进入产品构建。
