# 验收清单

本清单用于新工作区每次里程碑评审。通过门以真实行为为准，不以文档完成度代替。

## A. 产品边界

- [ ] 单用户模式不包含成员、团队、邀请或权限代码。
- [ ] Control 不内置通用聊天或 LLM Provider 管理。
- [ ] Project 只有 ACTIVE/ARCHIVED，没有科研阶段状态机。
- [ ] 新一轮实验通过 Plan Revision 表达，而不是回退 Project 状态。
- [ ] P0 页面只有 Board、Plan Workspace、Run Detail、GPU Servers。
- [ ] 高密度 Sidebar、横向看板、卡片和 GPU 服务器信息布局得到保留；若使用 Multica 源码或品牌，已有书面许可决策和对应授权。
- [ ] 看板列是 Plan/Job 的派生视图，不成为新的项目状态机。
- [ ] 不存在 Scholar/Reviewer/Executor 等常驻产品实体或多 Agent 状态机。

## B. 科研资产

- [ ] 项目可初始化 `.autolab/context.md`、`experiments/` 和 `knowledge/failures.md`。
- [ ] 实验记录包含假设、相对改动、baseline、指标、事前成功判据、风险和 fallback。
- [ ] Plan 批准时冻结实验记录 hash；批准后改文件不会改变已批准执行契约。
- [ ] 实验记录不保存 QUEUED、RUNNING、GPU Lease 或进程状态。
- [ ] 结果结论引用具体 Job、指标文件或 Artifact。
- [ ] 被否定方向记录失败原因、证据和重新考虑条件。
- [ ] 新会话无需原聊天记录即可恢复上一轮研究上下文。

## C. 计划与任务

- [ ] DRAFT Plan 能完整预览代码锚、命令、矩阵、GPU、并发、超时和输出规则。
- [ ] APPROVED Plan 不可原地修改。
- [ ] 重复批准不会重复生成 Job。
- [ ] Runner 已受理但响应超时时，Control 使用同一 dispatch_id 对账，不重复启动进程。
- [ ] 2 个数据集 × 3 个 seed 精确展开为 6 个 Job。
- [ ] retry 创建新 Job，并保留原失败 Job。

## D. 调度

- [ ] QUEUED Job 按稳定顺序调度。
- [ ] 同一 GPU 的活跃 Lease 不重复。
- [ ] Control 崩溃后 Lease 可以通过对账恢复。
- [ ] Runner 不可达时停止新派发。
- [ ] 用户可以取消 QUEUED Job 并停止 RUNNING Job。

## E. Runner

- [ ] 同一 dispatch_id 重放不启动第二个进程。
- [ ] 三个并发相同 dispatch_id 请求也只启动一个进程；异载荷返回冲突。
- [ ] 每个 Job 有独立进程组、日志和输出目录。
- [ ] Control 离线后 Job 继续运行并保存事件。
- [ ] TERM→KILL 停止链可验证。
- [ ] timeout 到达后 Runner 能独立终止任务。
- [ ] 工作目录和输出目录路径边界测试通过。
- [ ] 非 test mode 下空 Token/HMAC 无法启动 Runner。
- [ ] Runner 不维护等待队列，不与 Control 争夺调度权。
- [ ] 陈旧 PID 或 PID 复用不会导致误杀无关进程。

## F. 恢复与事实一致性

- [ ] Control 重启后自动恢复 RUNNING Job。
- [ ] 重复 Runner 事件不产生重复副作用。
- [ ] 游标过期时可以用 Runner snapshot 恢复。
- [ ] 本地状态不确定时显示 `observation_state=UNKNOWN`，但不覆盖 Job 执行状态。
- [ ] 不把“停止请求已发送”显示成“已停止”。
- [ ] 终态 Job 不因迟到事件回退。

## G. 日志、指标与产物

- [ ] 日志按 cursor 增量读取。
- [ ] 页面不会为新日志重新下载完整历史。
- [ ] Job 终态包含 exit code、耗时和失败摘要。
- [ ] JSON/CSV/正则指标注明来源。
- [ ] Artifact 包含路径、大小和 hash。

## H. GLM Agent 工具

- [ ] Agent 能列出服务器和项目。
- [ ] Agent 能通过受限工具读取/修改登记项目根内的文件并查看 Git diff，不能越界或获得通用远端 shell。
- [ ] Agent 能读取项目代码锚和上一轮结果。
- [ ] Agent 能读取项目 context、相关实验记录和失败经验。
- [ ] Agent 能创建 DRAFT Plan，但不能绕过批准产生 Job。
- [ ] Agent 只能请求审批；用户在本地 UI/CLI 确认准确 spec hash 后产生 Job，Agent 随后能追踪执行。
- [ ] Agent 能按需查看日志、停止和重试。
- [ ] 工具错误返回可行动的原因，而非内部状态机术语。
- [ ] 同一工具面通过本地 stdio MCP 暴露，不要求 GLM 直接调用私有 HTTP 细节。
- [ ] GLM API Key、Base URL 和模型选择只存在于 Agent 宿主配置中。
- [ ] GLM Coding Plan + Claude Code Agent 外壳可以连续完成 3 轮实验。
- [ ] 至少另一个支持 MCP 的 GLM 宿主能调用核心读工具和 `create_plan_revision`，无需修改服务端 schema。

## I. 前端性能

- [ ] 看板直接消费轻量 `BoardCardView[]`，不经过通用 IssueSurface 查询系统。
- [ ] Overview 首屏只有 1 个业务请求。
- [ ] 其他核心页首屏不超过 3 个业务请求。
- [ ] 页面冷启动可交互时间小于 1 秒。
- [ ] 普通按钮反馈小于 200ms。
- [ ] 无全局 `invalidateQueries()` 或等价全站失效。
- [ ] Job 事件只更新相关 Job、Plan/Project 摘要。
- [ ] 实时连接正常时无固定 5 秒轮询。
- [ ] 1000 个历史 Job 下性能目标仍满足。

## J. 安全和数据

- [ ] Control 只监听 loopback。
- [ ] 非 health API 受 capability token 保护，并区分 agent/owner scope；MCP 的 agent token 无法调用 owner 接口。
- [ ] SSH/Runner 密钥不进入日志、API 响应或 Git。
- [ ] SSH 首次连接展示/确认主机指纹，后续固定指纹；不存在 `known_hosts=None`。
- [ ] 凭据通过系统钥匙串或 0600 文件保存。
- [ ] 删除和强制停止操作具有明确资源 ID。
- [ ] 普通 MCP 不暴露 Plan 批准、删除凭据、覆盖产物等人类高风险入口。
- [ ] 新工作区未复制旧数据库、runtime.json 或 credentials。

## K. 真实使用通过门

- [ ] 本地双进程 E2E 连续通过 20 次。
- [ ] 至少一台真实 GPU 服务器完成任务。
- [ ] 至少一次 Control 中断恢复成功。
- [ ] 至少一次 RUNNING Job 停止链验证成功。
- [ ] 连续完成 10 轮“修改—训练—结果—再修改”。
- [ ] 10 轮过程中没有因为新增高级科研功能阻塞基本训练队列。
