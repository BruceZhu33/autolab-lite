# 新工作区开工指令

把下面内容作为新工作区的第一条任务指令：

---

这是一个全新的 AutoLab Lite 工作区。请先完整阅读：

1. `docs/reboot-source/00-产品决策摘要.md`
2. `docs/reboot-source/01-产品需求-v1.0.md`
3. `docs/reboot-source/02-目标架构与数据模型.md`
4. `docs/reboot-source/03-资产清单与迁移边界.md`
5. `docs/reboot-source/04-迁移与迭代计划.md`
6. `docs/reboot-source/05-验收清单.md`
7. `docs/reboot-source/08-交给编码AI的开工方案.md`
8. `docs/reboot-source/09-v1.3审查修订与决策门.md`

本项目不是旧 AutoLab 的继续扩建。禁止复制旧 `ui`、数据库 migrations、状态机、RD-Agent 或旧 gpu-agent 作为生产模块。`source-assets/contracts-v1/` 是规范协议；`gpu-agent/`、`control-reference/`、`tests-reference/` 和 `contracts-reference/` 全部只作参考。

Multica 源码、截图和品牌图标受许可决策门约束。M5 前不得解压源码快照、复制组件、使用 `source-assets/brand/` 或做像素级复刻；本轮 M0/M1 完全不处理 UI。

研究语义与运行事实必须分开：目标、假设、成功判据、结论和失败经验进入项目 `.autolab/` 文件；批准、队列、GPU Lease、进程和退出码进入 Control SQLite。UI 只做投影。同一状态禁止在文件、数据库和前端重复维护。

产品第一优先适配 GLM Coding Plan。M4 通过本地 stdio MCP server 接入，首个验收宿主使用 Claude Code，但模型是 GLM；AutoLab 不保存 GLM API Key，也不实现模型代理。M0/M1 只实现 CLI 和底层工具能力，不提前接模型。

当前目标是完成 M0 和 M1：

- 建立 control、runner、protocol、client/CLI 和 tests 骨架；
- 建立最小 Research Workspace Protocol：context、experiment、failures；
- 定义最小 Plan v1、Manifest v1、Runner Event v1；
- 直接采用并测试 `source-assets/contracts-v1/`，不得兼容旧 `/attempts` 协议；
- 只建立需求规定的最小数据表；
- 先用 local transport 跑通真实 Control + Runner 双进程；
- 实现计划批准、Job 展开、FIFO 调度、GPU Lease、幂等派发、事件接收、日志和产物；
- 本轮 `plan approve` 是用户使用 owner scope 主动执行的交互式 CLI 操作；未来 MCP 只获得 agent scope，不得暴露该人类批准入口；
- M0/M1 暂时不做 Web UI，但不得删除或忽略交接包中的 Multica Shell 参考资产；
- 重写本地 E2E，并连续运行验证无重复派发和 Lease 泄漏。
- 只完成 `08-交给编码AI的开工方案.md` 中的 M0/M1，不自行提前进入 SSH、Agent UI 或 Multica 迁移。
- 新 Runner 必须 fail-closed、无内部等待队列、校验路径边界；不得把旧 Runner 整目录复制后改名。

每次准备增加表、状态、Provider 或页面前，都要指出它对应哪个当前用户动作。不能用未来可能需要作为 P0 的实现理由。

先检查新仓库现状，给出一个按可运行纵切切分的实施计划，然后直接开始 M0；不要回到旧工程做原地修改。

## 建议复制方式

若收到的是压缩包，先在新仓库中建立文档目录，再把包内容放入其中：

```bash
mkdir -p NEW_REPO/docs/reboot-source
tar -xzf /path/to/next-workspace-kit-v1.3.tar.gz -C /tmp
cp -R /tmp/next-workspace-kit/. NEW_REPO/docs/reboot-source/
```

不要移动任何 reference 目录到生产源码。正式 `runner/` 必须根据 `contracts-v1/` 和 `gpu-agent/REFERENCE_ONLY.md` 从测试出发实现。`ui-reference/multica-shell-source-reference.tar.gz` 原样留在文档目录，M5 许可决策前不得解压。其他 reference 资产继续留在文档目录，避免被误认为生产代码。
