## 1. 架构与三权限域（U3：双 scope 全覆盖；test 读取后继续开发=只能开新实验版本并标记原测试集已参与开发）

```
用户控制机：Tauri 壳 → Next 前端(static export) → sidecar(FastAPI+SQLite+RD-Agent 提案引擎)
            sidecar 仅绑 127.0.0.1 随机端口；capability token 保护全部非 /healthz API 与 WS（B2）
SSH 隧道 → GPU 服务器(Linux)：gpu-agent（主进程以低权限 autolab-agent 运行，仅最小 launcher 持三身份切换权；监听签名校验）
```

**执行身份（服务器上三个 Unix 用户，评测资产属主 root:autolab-agg 0640 + 目录 ACL 只读（agg 可读，任何执行身份不可写）**

| 域 | 能看 | 跑 |
|---|---|---|
| train | 训练/验证输入与标签（训练面） | 候选代码训练演化 |
| candidate-infer | **scope 对应的无标签输入**（val 输入或 test 输入） | 加载候选 ckpt 出 predictions |
| trusted-aggregate | **scope 对应标签** + 冻结指标代码 | 算指标；永不加载候选代码 |

**验证与测试同构走三域（U3 核心）**`scope=val` 指标可信后允许进 JUDGE/候选选择；`scope=test` 结果存隔离数据面，**仅最终确认事务一次性释放**——`POST /final-confirmation/read` 原子完成：读取 test 结果 + 项目状态迁移到 `FINISHING`（**离开一切可开发状态，不可回 SEARCH/换候选**）+ 写 `test_result_releases` + `audit_events`。无 sudo 降级模式：**仅诊断运行**——不产 trusted 指标、禁止候选确认与科研结论（D29 为硬要求，风险提示不能替代）。

## 2. 控制权时序

RD-Agent（版本锁定）仅返回 {analysis, patch_diff}；产品层显式执行：JUDGE 三查(CAS) → 应用 patch → 冒烟 → commit+code_snapshot → 预算事务 → 组装签名清单 → 派发 attempt → agent 事件回传(inbox 幂等) → 评测调度(infer+agg 双步) → trusted 指标入库 → 齐套判定 → 状态迁移(CAS+outbox)。

## 3. 数据模型（逻辑实体清单，七组；**SQLite DDL/FK/CHECK/UNIQUE/trigger/迁移脚本为编码前第五契约**）

**核心**`servers` `gpus` `projects` `project_gpus`

**执行**`runs(round_no, role, plan_protocol_id, code_snapshot_id, env_version_id, data_version_id, recipe_id, init_spec_id, candidate_id, control_epoch, status)` · `training_recipes(不可变：budget_ep, pretrain_src, optimizer, augment, precision, selection_rule)` · `initialization_specs(kind, parent_attempt, ckpt_hash, load_report, optimizer_state_ref, cum_steps, seed_train, seed_infer)` · `attempts(run_id, seq, dispatch_id UNIQUE, evaluation_request_id NULL, server_id, profile[train|infer|agg], exec_manifest_hash, control_epoch, budget_reservation_id NULL可延迟, status)` · `artifacts(attempt_id, kind, path, sha256, protected)`
**科研身份与批次（D36/D45）**`candidates(proto_id, selection_rule_ver, selected_run_id, status)` · `modules(identity, code_refs)` · `ablation_matrices(proto_id, version, body_hash, frozen_at, status)` · `ablation_items(matrix_id, module_identity, config_json)` · `ablation_item_runs(item_id, run_id)`（多 seed 关联）· `batches(candidate_id, plan_protocol_id, recipe_id, matrix_id FK, init_spec_id)`——五绑定齐（U-B1）· `batch_items(batch_id, run_id, expected_role, expected_seed, status, fail_reason)`· `seeds_registered(proto_id, role, seed_set_json)`
**评测（U-B2/U-B7）**`evaluation_requests(id, run_id, scope, plan_protocol_id, data_version_id, split_id, ckpt_artifact_id FK, ckpt_expected_sha256, evaluator_digest, ckpt_selection_rule_ver, status)`（**冻结完整评测身份**——签名清单自此生成；infer/agg attempts 以 evaluation_request_id 关联之，证明两步同源；evaluation_results 只回填 value/evidence，不得另声版本份）· `evaluation_results(evaluation_request_id, metric, value, evidence_hash, UNIQUE(evaluation_request_id, metric))`——版本身份一律经 request 获取，不冗余存储（如为查询性能冗余，trigger 强制与 request 相等）——attempt 重试不产生重复正式指标 · `splits(proto_id, name, unit_rule, preprocess_fit_scope)` · `split_validations(plan_protocol_id, data_version_id, split_id, validator_version, status, evidence_hash, validated_at, UNIQUE(四元组))`——guard 只读此表有效 PASSED · `data_replica_validations(data_replica_id, manifest_sha, verifier_ver, status, checked_at)` · `baseline_acceptances(run_id, verdict, patch_class, notes)` · `review_evidence(retrieval_mode, query, sources_json, checked_at)`
**预算（单权威，U-B3/U-B4）**`budget_accounts(limit_s 权威, status[ACTIVE|DRAINING], requested_limit NULL, drain_started_at, consumed_s, reserved_s, revision)`——同事务不变量：ACTIVE⇒requested IS NULL；DRAINING 禁新 reserve；STOP_CONFIRMED/硬截止后才减 reserved；C+R≤limit_s 恒成立；满足后原子回 ACTIVE · `budget_reservations(attempt_id UNIQUE, authorized_s, remaining_s, status, expires_at)`——STOP_REQUESTED 期间**继续计入 R** 直至停止确认/硬截止结算 · `usage_events(attempt_id, seq, cumulative_s, UNIQUE(attempt_id,seq))`（agent 自采样）。降预算两阶段（V6）：①写 requested_limit，账户入 DRAINING（limit_s 不变）②禁新授权，循环对最大预留发 STOP 直至不等式可满足 ③结算后原子更新 limit_s=requested_limit；新限 < C 直接拒绝（历史消耗不可回退）；DRAINING 期间 STOP 未确认的预留继续计入 R
**失效与审计与基础设施（U-B7/V2）**`outbox(id, idempotency_key UNIQUE, aggregate_type, aggregate_id, op, payload, status)` · projects/runs/attempts 均含 `state_revision` · `predictions` 为受控 artifact（绑定 evaluation_request_id + infer_attempt_id + sha256 + canonical 格式版本 + 样本 ID 列表 hash + 行数，aggregate 只读该确切 artifact）；attempts 约束 `CHECK((profile=train AND evaluation_request_id IS NULL) OR (profile IN (infer,agg) AND evaluation_request_id IS NOT NULL))`，每 request 至多一个成功 infer/agg attempt——以**部分唯一索引**实现（成功态 (request_id, profile) 唯一），普通 UNIQUE 会挡合法重试· `invalidation_edges(cause_type[protocol|candidate|recipe|data_version|method], cause_id, invalidated_kind, invalidated_id, revalidate_status)` · `audit_events(actor, action, payload, t)` · `test_result_releases(batch_id UNIQUE, release_payload_hash, released_at, released_by)`——重试返回同结果且可验证内容未变——库级保证一次性释放 · `agent_inbox(agent_instance_id, event_seq, UNIQUE)` + `agent_cursors`

## 4. 状态迁移表（U4 —— 全表入档；命名规范：PAUSED 为唯一项目暂停态，PAUSED_MANUAL/矩阵修订等为 pause_reason 子字段；停止等待分层：PROJECT_STOP_PENDING（项目态）/ ATTEMPT_STOP_UNKNOWN（attempt 态），恢复逻辑不得互相投影。正式状态表须机器可检查（S5）：每状态列全 允许事件/guard/事务写入/outbox/回滚/幂等重放；校验 非终态可达出口、STOPPING/DRAINING/等待态的超时与人工接管、重复 terminate/cancel/resume 不回退、重启仅凭持久态恢复）

格式 `from +event [guard] → to (+outbox)`；每次迁移记录 event_id/actor/reason/occurred_at/expected_revision（UI 回放与事故审计）。**项目层**
```
INIT +start_env_setup → ENV_SETUP；+setup_done → REVIEW_GATE
REVIEW_GATE +confirm[D21][plan_frozen ∧ split_validation=PASSED(绑定 proto+data_ver+split+validator_ver，变更即失效) ∧ 全部所需 data_replicas=READY ∧ evaluator_snapshot_frozen] → BASELINE_ACCEPTANCE
BASELINE_ACCEPTANCE +accept[D33] → SEARCH；+reject → PAUSED_MANUAL
SEARCH +candidate_selected[D37] → CONFIRMATION_PREP；CONFIRMATION_PREP +batch_frozen[D45 五绑定] → CONFIRMATION_RUNNING
CONFIRMATION_PREP +matrix_revision_required → PAUSED(matrix_revision)
CONFIRMATION_RUNNING +protocol_or_method_changed → PAUSED(revision_required)
CONFIRMATION_RUNNING +all_required_results_ready[D34 齐套] → TEST_RESULT_SEALED
TEST_RESULT_SEALED +final_read(idempotency_key)[guard：候选已选/批次冻结/全部指定 batch_items 齐套/协议未失效/无未决方法变更；单事务：写 release/audit、返回固定结果、关闭开发路径] → FINISHING(completed|failed)
任意非终态(含 ENV_SETUP/REVIEW_GATE/BASELINE_ACCEPTANCE/SEARCH/CONFIRMATION_*/TEST_RESULT_SEALED/REPORTING/PAUSED) +terminate(reason) → 统一项目终止事件：
  [has_active_attempts] → STOPPING(reason)(+stop 全部活跃 attempt+冻结派发)；[no_active_attempt] → FINISHING(reason)
STOPPING +all_attempts_terminal_or_stop_confirmed → FINISHING(reason)
STOPPING +agent_unreachable → STOP_PENDING_CONFIRMATION
STOP_PENDING_CONFIRMATION +reconciled_stopped[all_attempts_terminal 全机] → FINISHING(reason)；+reconciled_running → STOPPING(reason)(+retry_stop)；+still_unreachable → 自持
FINISHING +report_requested → REPORTING(+generate_report)；REPORTING +report_done → REPORTED(outcome)  // REPORTED 唯一终态；REPORTING 中重复 terminate 仅更新 reason 不迁移（防循环）；report_failed→重试或 PAUSED(manual)
SEARCH/BASELINE_* +pause[D8 条件] → PAUSED(reason)
PAUSED 四个独立事件（正式契约不得合并为一个 resume 接口）：+resume[无待应用修订]→原状态；+apply_control_revision[不中断候选资格]→原状态(epoch+1)；+apply_protocol_revision[失效传播]→REVIEW_GATE/BASELINE_ACCEPTANCE；+apply_method_revision[新 candidate 先重验 D37，未满足→SEARCH]→新 batch→CONFIRMATION_PREP；+revise[D38] → 协议变更走 invalidation 后回 REVIEW_GATE 或 SEARCH(依变更类型)；+terminate → 走统一项目终止事件（见上，含 STOPPING 分支）
```
**run 层**`PLANNED→…→JUDGED`；JUDGED 出口：`+continue → 新 run:PLANNED`、`+candidate_selected → 项目层 CONFIRMATION_PREP`、`+terminate(reason) → 统一项目终止事件(由项目层按并行 attempt 决定 STOPPING/FINISHING)`；分流：`REPAIRING[entry: model 失败∧retry<3; exit: 冒烟过→QUEUED | 超限→项目层 PAUSED_MANUAL]`、`INFRA_RETRY[entry: infra 失败∧retry<N; exit: 换机重派→QUEUED | 超限→PAUSED_MANUAL]`、`METRIC_MISSING[D24 阻断→人工/适配修复→EVAL_QUEUED]`、`LLM_BACKOFF[entry: LLM 服务错误；exit: 退避到期重试成功→resume_state 记录的原调用点(分析/评审/修复) | 上限→跨层 pause 事件→项目层 PAUSED(manual)]`
**attempt 层**`SUBMITTED(+cancel[outbox 未投递则同事务撤回本地终结；可能已投递才走停止链]可取消→ACKED→REMOTE_QUEUED→RUNNING→FINISHED|FAILED`；停止链自 `SUBMITTED|ACKED|REMOTE_QUEUED|RUNNING` 均可 `+stop → STOP_REQUESTED→STOP_SENT→STOP_CONFIRMED`

**竞态裁决（U4 列名场景）**① 项目 pause 时在跑 attempts **继续至完成**（结果照收），仅停止派发新 attempt；② 自然完成与停止并发按**事件因果**裁决：waitpid 先于 stop 信号送达 → FINISHED；信号已送达并导致退出 → STOP_CONFIRMED（即使 rc=0，进程可捕获信号假退）；无法确认 → STOP_PENDING_CONFIRMATION；③ 批跑单项失败：不传染兄弟项，批次状态按 batch_items 聚合（全部成功/部分/失败），项目取消时对全部活跃 attempt 发停止链；④ 修订传播分轨：控制约束（预算/暂停/取消）按 control_epoch；科研可比性与 D44 失效按 plan_protocol_id（旧协议在途 attempt 可完成但结果不入新协议比较集）；方法一致性按 candidate_id+recipe_id+init_spec_id+matrix_id。

## 4.5 agent staging（D30/D40 运行时隔离，Y1 恢复）

- code：按 code_snapshot.export_hash 展开至 staging，执行前校验，运行身份**只读**挂载。
- env：版本目录只读；任务内 pip/conda 原地修改被拒（写权限剥离）。
- data：replica 以 data_version_id 只读绑定，执行前**重新校验 manifest**。
- output：每 run/attempt 独占可写目录；cwd 禁止符号链接逃逸；清理命令仅可作用于 output 根（参数化白名单）。
- BASE 原目录与数据主副本不在任何执行身份可写路径上。
- **OS 级强制（Z1）**每 attempt 由最小 launcher 经 systemd transient unit（或等价沙箱）启动：ProtectSystem=strict、ProtectHome=true、PrivateTmp=true、ReadOnlyPaths=code/env/data、ReadWritePaths=output+run-cache、NoNewPrivileges=true；HOME/TMPDIR/XDG_CACHE_HOME/TORCH_EXTENSIONS_DIR 重定向至 attempt 独占目录。sandbox 策略 hash 入签名清单（可追溯）。agent 启动探测 systemd transient-unit 与沙箱能力，缺失即仅 diagnostic mode；/healthz 返回能力清单+策略 hash；"等价沙箱"最低语义=mount namespace 隔离+只读绑定+可写白名单+NoNewPrivileges。评测域（infer/agg）默认**禁外网**，仅显式白名单端点。
- 同步状态机（D39）：SYNCING → VERIFYING → READY | FAILED，临时目录校验后原子 rename 发布。
- sidecar 生命周期（恢复）：启动握手(/healthz+schema_ver)、崩溃后凭 DB+agent_inbox 恢复、优雅退出=停派发+对账+落盘。

## 5. gpu-agent 契约

`GET /healthz{agent_ver,schema_ver,capabilities}` · `GET /events?since_seq&agent_instance_id`（保留期与 cursor 过期返回显式错误+全量 snapshot 格式，U-O3）· `POST /attempts{dispatch_id 幂等, profile, manifest{全部绑定引用}, manifest_hmac：对执行清单规范化完整字节签名（canonicalization 带版本号；密钥轮换设重叠期，防升级期序列化差异误拒）（含全部版本引用、profile、deadline、预算额度、dispatch/agent/key ID、issued_at、expires_at）, deadline_at, budget{reservation_id, authorized_s}}`——agent 持久化已用 dispatch_id 防重放/跨服务器转发（U-B5）· `GET /attempts/{id}?tail=` · `POST /attempts/{id}/stop`（三段停止链）· usage 为 agent 自采样事件。

## 6. sidecar API

`/api/v1` 统一前缀；request_id/run_id/attempt_id/event_seq 统一标识；capability token 全覆盖（除 /healthz）。scope=test 读取仅 `POST /api/v1/projects/{id}/final-confirmation/read`（§1 原子语义；幂等键保证事务已提交但响应丢失时重试返回同一释放记录）。**四件套（OpenAPI v1 + 验收场景映射 + plan JSON Schema + WS 事件契约）= M1 第一批工作包，复审通过前不写业务代码**（U5）。
