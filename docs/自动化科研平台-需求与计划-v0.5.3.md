## 1. 产品定义

**一句话**：用户给出大方向、BASE 代码和论文、模块想法；平台与用户对话式评审确定方案；
定稿后全自动连接多台局域网 GPU 服务器排队训练、监视、分析日志、自主修改模型（结构级）并再训练，
直到触发终止条件；随后自动执行评估、消融、多 seed 确认，并自动生成论文级科研图表与实验报告、可复现代码包。

**边界**：平台只管理"在产品内迭代的模型"。BASE 代码、数据、服务器均为用户资产，
平台按项目绑定使用，不做通用资源管理。

## 2. 核心流程总览

```
[0] 服务器/GPU注册 ─▶ [1] 立项(BASE+GPU卡池+论文+方向) ─▶ [2] 远程环境搭建
                                                        │
   [7] 产出物(报告+图表+代码包) ◀── [6] 评估·消融·多seed ◀── [5] 终止判定
                                                        ▲
   [3] 对话式方案评审 ──▶ [4] 全自动训练闭环(排队→监视→分析→改码→再训练) ──┘
```

## 3. 分阶段需求

### [0] 服务器注册与管理（UI 页面模块 P1）
- 登记多台 GPU 服务器（SSH 主机名/IP、账号、密钥/密码），一键测试连通性。
- 实时 GPU 状态：每台的卡数、每卡显存/利用率、当前占用（哪个项目哪个任务在用）、已装环境列表。
- **调度模型（定案）**：以单张卡为调度单位，一张卡 = 一个队列；一个训练任务占一张卡；
  多卡 = 多任务并行铺开。项目立项时从已注册服务器勾选 GPU 卡池，**卡池可跨服务器**。
- **多项目共享仲裁**：多个项目勾到同一张卡时先到先得排队；项目可设优先级，高优先级任务可插队。
- **机器就绪状态（A11）**：每台机器对每个项目维护"代码+环境+数据"就绪状态；搭建部分失败时重试只修复失败步骤，不影响已就绪部分与在跑任务；卡池运行中新增机器须完成校验后才可接单；凭据变更后重新验证连接并保留失联任务记录。**启动策略（R11）**：项目在 plan 中声明——默认"全池就绪后启动"，或"允许满足同一实验协议的可用子池运行"（仍须满足任务硬件约束与效率评测要求）；移除有在途任务的卡，默认"停止派发 + 排空后移除"，用户显式取消才立即终止在途任务。
- **外部占用识别（A03）**：GPU 状态区分"平台任务占用"与"外部进程占用"（用户手动启动的进程），后者不进平台队列但显式标注，避免误判空闲；资源需求超出全池时明确阻塞原因与处理入口，不静默排队。
- 已定案（原 T1）：仅支持局域网直连，不做跳板机/多级跳转（用户日常即一条命令直连 SSH）；
  本机主服务与服务器上 agent 的通信走 SSH 隧道（复用 SSH 通道，免开防火墙端口、流量加密）。

### [1] 立项（UI 页面模块 P3）
- 输入：项目名 + 大方向自由文本（结构化细节留给 [3] 评审追问补齐，见 D18）+ BASE 代码来源（GitHub URL 或本地工作区路径，二选一）+ GPU 卡池勾选（可跨服务器，D15）+ 数据集登记（主副本所在机器与路径，D16 自动复制的源）+ 论文（arXiv/DOI/期刊链接优先，系统自动抓 PDF 与元数据；抓不到的（付费墙等）或本地 PDF 手动上传兜底，见 D17）。
- BASE 导入语义（定案）：系统将 BASE 代码**复制快照**进产品管理的项目库作为基线——GitHub 来源克隆；本地目录整体复制；非 git 仓库则 git init + 基线提交。**用户原目录永不被自动化改动**（贯彻"产品只管产品内迭代的模型"）。
- 不在立项时做"能否跑通训练"的预检查——由 [2] 环境搭建末尾的冒烟验证兜底，避免重复设计。
- 系统行为：导入 BASE 基线仓库；论文抓取/上传 → 解析入库（全文抽取、方法/指标结构化、元数据补全）。
- 产出：项目档案（基线仓库快照 + 文献库）。

### [2] 远程环境搭建
- 用户在项目里选择"搭建环境"，系统对**卡池涉及的每一台服务器**分别完成：
  依赖识别（requirements.txt / environment.yml / setup.py 等）→ 创建隔离 conda 环境（见 D20）→ 安装依赖 → 上传 BASE 代码 → **数据版本校验通过（D39，训练相关验证的前置条件）** → 冒烟验证（最低标准：可 import、跑通 1 个 step；[4] 每轮改码后的冒烟按增强标准执行——前向、有限 loss、反向、预期可训练参数的梯度与更新、checkpoint 保存重载、最小评估链路；任务语义相关的检查由适配配置声明，能力以 BASE 代码为准）。
- 环境与项目绑定，多项目互不干扰；环境配置留档（可复现）。跨服务器卡池意味着：卡池里每台机器都要有同构环境与代码副本，系统负责保持同步。
- **跨服务器对齐的四层义务**：① 代码对齐（派发前同步到执行机，且每个 run 使用独立快照保证运行期不变，见 D40）；② 环境同构（CUDA/驱动/PyTorch 组合兼容，异构卡池需分环境配置；环境按版本管理）；③ **数据版本一致（D39，"路径存在"≠"同一版本"）**：登记文件清单与校验和，先同步到临时位置、校验通过后原子发布，运行中的副本禁止更新，支持逻辑路径到各机器实际路径的映射，手动放置同样要过校验（D16 自动复制按此标准执行）；④ GPU 异构防护（勾卡界面展示型号/显存，任务可声明显存下限，调度过滤；结构修改后更新资源需求，不静默改科研配置适配小卡）。

### [3] 对话式方案评审（人机协同定稿，UI 页面模块 P4）
- 用户输入模块想法（自然语言，可粗可细，可一次给多个）。
- **两段式评审（D22）**：
  - 第一段·逐模块：每个模块单独走一轮"方案初稿 + 反问清单 + 文献对照"，单个模块被否不影响其余模块；
  - 第二段·整体汇总：全部模块过完后系统合成整体方案，检查模块间冲突与组合风险，用户整体过目。
- 每轮产出：模块设计方案 + 反问清单（指标定义、数据划分、预期量级、风险点）+ 文献对照结论（想法查重、可借鉴方法、论文报告指标参照）。
- **文献检索范围（D42）**：查重/对照支持两种模式按项目选择——"仅已导入文献"或"外部检索"（arXiv/Semantic Scholar 等）；查重结论必须标注检索范围与时间，"未发现相似工作"不得表述为"创新性成立"；论文指标保留数据集版本/划分/评估协议/训练条件，不只抽最高分进基线表。
- **定稿闸门（D21，原 T3）**：反问清单全部回答、整体确认后，用户显式点击"确认定稿"才生效——常规流程进入全自动阶段前的最后一道人工闸门。定稿后的自治表述（Q03 统一）：**常规研究步骤自动执行；触发预设暂停条件、需要人工协议修订、或消融矩阵需修订确认时等待用户**。定稿产物为 experiment_plan，字段契约（A01）：目标指标与方向、数据集与划分协议（含独立单位/分组或时间规则、划分清单与跨集合对象交叉校验，见 D43）、训练/评估命令模板、工作目录、seed 与随机性协议、指标 schema 或日志正则、checkpoint 位置与恢复命令、退出码约定、基线与公平比较口径（D33）、终止条件、消融矩阵、最终比较与证据规则（主指标与方向、差异计算方式、最小关注改进、约束指标、误差/区间或检验方法，Q01）、评审结论留档。
- **定稿后修订（D38，版本化）**：experiment_plan 允许人工修订（如终止参数配错）；每次修订生成不可变 plan_version，每个 run 绑定其执行时的版本。控制类变更（降预算、发起停止）立即约束后续执行；协议类变更（指标、数据划分、seed、消融矩阵）只对新轮次生效，旧队列任务按版本归属处理，涉及可比性的结果不跨版本合并。协议类变更触发**转移规则（D44）**：受影响的基线、候选排序与消融结果失效，进入新的对照验收；数据划分变化时检查继承权重的训练数据来源，必要时回合规初始化重训；控制类变更不触发科研对照重跑。

### [4] 全自动训练闭环（产品核心，UI 页面模块 P5）
- 队列与执行：任务提交到项目卡池（一任务一卡，空闲卡即取）；**迭代主循环串行**（下一轮改码依赖上一轮结论，D15），评估/消融/多 seed 等批跑阶段并行铺满卡池；持续监视队列与训练状态。
- **Round 0 基线训练与验收（D33）**：迭代开始前先跑 BASE 原版（不改码），其指标作为全程对照基线——支撑 D27"未超基线"终止判定与基线对比图。完成**基线验收**（训练行为正常、数据/指标协议与定稿一致、基线配置合理非"跑坏的 BASE"）后才开始自动搜索；与论文报告数值不一致时记录可解释差异，不强行要求完全复现。Round 0 自身出错时区分**环境兼容补丁**（路径/依赖适配：保留原快照、独立补丁版本与理由，验收后使用）与**方法修改**（Round 0 禁止）；无有效基线前，阻断依赖基线的自动判定与优越性结论。Round 0 验收后，**先实现定稿方案并核对模块清单（"方案落成 Round 1"），才进入自由迭代**；发现方案不可实现或需改核心假设时转入 D38 方案修订流程（R08）。公平比较口径（R10）：后续训练配方变化（训练预算、预训练来源、优化器与数据增强、数值精度、模型选择规则）须披露，结构收益主张需要时补采用相同配方的 BASE 对照；父权重续训记录累计步数与优化器/调度器状态，不只记权重文件。
- 每轮流程：
  1. 训练结束 → 拉取日志与指标曲线；**用于终止判定、跨轮比较与候选选择的正式指标必须来自 D29 可信评测来源**（附带 run、数据版本、评测协议版本），D24 的日志/文件解析值仅作诊断展示（R01）；
  2. **先判定后行动（D32）**：本轮有效结果入库后先检查 [5] 终止条件、取消状态与剩余预算，未终止才继续；
  3. **LLM 全自由决策**（输入上下文见 D25）：自主判断问题与改进方向；
  4. 生成代码修改（**结构级**：网络模块、层数、损失函数等，全仓库开放，无预置冻结区；**但不得触碰受保护的评测协议**——数据划分、指标算法、测试集，见 D29）；
  5. 改动入链式血缘（每轮 = 基线仓库一个 commit，链式累积；重要节点自动存检查点，可回滚）；**每 run 声明权重初始化协议**（从头训练/父权重续训/预训练迁移，见 D35），结构不兼容时按批准的迁移规则处理并产出加载报告，禁止静默部分加载；
  6. 冒烟验证通过（增强标准：前向、有限 loss、反向、预期可训练参数的梯度与更新、checkpoint 保存重载、最小评估链路）→ **派发前再查取消状态与预算** → 自动入队下一轮训练；不通过 → 走自修复路径（D23）。
- **两种坏结果分流（D23）**：训练崩溃（NaN/OOM/报错）→ **先按 D41 分类，仅模型/代码错误进入 LLM 自修复（上限 3 次）**，仍失败暂停等人工；训练正常但指标不佳 → 正常迭代路径。崩溃不计入"无提升轮数"配额，避免机器白痴错误提前终止研究。
- **失败四分类（D41）**：模型/代码错误（进 D23 自修复）｜基础设施错误（断电/磁盘满/服务器失联：限次重试或换可比执行机，不改模型）｜指标提取错误（**区分正式/诊断，Q04**：正式决策指标缺失→阻断下一轮改码；诊断字段缺失→降级展示或进诊断修复，被启用的判定器依赖该字段时按其缺失规则处理，不得视为满足条件；日志缺失与可信评分失败在 UI 显示不同原因）｜LLM 服务错误（退避重试；输出完整校验后才应用，断流不留半个补丁）。失败尝试不计"无提升轮数"，但计入预算与健康统计。
- **运行隔离（D40）**：每个 run 使用独立的代码/配置快照（**运行期间不可变**）与**独占可写的输出目录（完成后封存）**，环境按版本管理、禁止有任务在用时原地升级；任务绑定 commit、环境版本、数据版本（D39）与 plan 版本（D38）。
- 每轮单 seed 快速验证（seed 预先登记，见 D34）。
- 全程审计：每轮 diff、LLM 分析结论、决策理由永久留档，UI 可回放。
- **训练产物与磁盘管理**：checkpoint/日志留存执行服务器项目目录，指标与最优 checkpoint 回收归档；磁盘清理按引用关系保护 BASE、最终候选、续训依赖与人工固定的产物，归档校验完成才允许删除远端副本，不能安全释放空间时暂停接单（防磁盘打满拖垮全部训练）。
- 紧急停止：UI 一键停止迭代 + 终止该项目在服务器上的进程组；远端停止须回执确认，失联期间显示"停止待确认"，不虚报已停止（D31）。

### [5] 终止判定（条件库，见 D27）
共 **17 项**条件（资源 4 / 进展 7 / 健康 4 / 人工 2），在 experiment_plan 中按项目**启用 + 配参**；**GPU 时长预算为强制项，不可禁用**。任一启用的条件触发即执行其配置的动作，动作分两档：**终止**（停止迭代）/ **暂停**（停下等人工决定继续或终止）。
**终态分流（D32）**：终止细分为"正常完成"（自动进入 [6] 评估）与"资源耗尽/用户取消/失败停止"（**不自动启动** [6] 的耗卡任务，用户可人工发起有限评估；取消操作不得隐式启动任何新训练）。预算范围覆盖 Round 0、修复尝试、冒烟、评估、消融与多 seed。**任何终态均可产出阶段报告（Q05）**：基于已归档数据自动生成终止原因、已完成/未完成实验清单、累计资源消耗与当前可用候选；未执行的消融/多 seed 标记为未完成、不伪造图表；不为补报告隐式启动训练；LLM 预算耗尽时用确定性模板汇总（额外 LLM 调用仍受预算约束）。
**判定器规格（A05）**：每个条件须定义指标方向、比较对象（默认对**历史最好**而非上一轮）、统计窗口、最少有效轮数、阈值单位（绝对/相对）、触发优先级（人工取消与硬预算 > 科研成功条件）与计数重置条件；不可比的训练曲线不触发跨轮过拟合判定；摇摆检测比较方案/结构身份而非文字摘要。
**预算与取消的执行责任（R02，记账口径 Q02）**：定义三个量——累计已消耗 C、活跃任务未消耗预留 R、总预算 B；约束为 **C + R ≤ B**，**可分配余额 = B − C − R**。新任务只从可分配余额原子申请授权（增加 R）；执行中实际消耗从 R 转入 C；任务结束或授权失效后按 D31 对账规则结算释放（失联期间不释放仍有效的授权）。**远端 agent 独立执行截止时间/额度**，控制端失联不豁免；声明计时口径、终止宽限与允许的计量误差；取消与派发定序，已取消项目的旧回调不得再提交新任务。

**资源预算类**
| 条件 | 含义 | 建议默认动作 |
|---|---|---|
| 最大轮数 | 兜底必填，如 20 轮 | 终止 |
| GPU 时长预算 | 累计 GPU·卡·小时 | 终止 |
| 墙钟时间预算 | 项目连续运行总时长（如 72h） | 终止 |
| LLM 费用预算 | 累计 token/费用上限（每轮分析+改码都耗） | 暂停 |

**科研进展类**
| 条件 | 含义 | 建议默认动作 |
|---|---|---|
| 目标指标达成 | 主指标达到目标值 | 终止 |
| 连续 N 轮无提升 | 主指标停滞 | 终止 |
| 收敛平台期 | 连续 N 轮提升幅度 < ε（边际收益低） | 终止 |
| 未超基线 | 连续 N 轮打不过 BASE 基线（方向可能走死） | 暂停 |
| 过拟合背离 | train 持续升 + val 持续降，连续 N 轮 | 暂停 |
| 指标显著回退 | 主指标连续 N 轮明显变差（大概率改坏） | 暂停 |
| 帕累托停滞 | 多指标场景（如精度×时延）前沿 N 轮无推进 | 终止 |

**健康度类**
| 条件 | 含义 | 建议默认动作 |
|---|---|---|
| 崩溃率过高 | 最近 M 轮崩溃占比超阈值（跨轮统计，区别于 D23 单轮内 3 次自修复） | 暂停 |
| 摇摆检测 | 在 ≥2 个方案间来回切换 ≥ K 次（A→B→A） | 暂停 |
| 单轮训练超时 | 单轮训练墙钟超上限（记为失败事件，按 D23/D41 分流处理） | 按失败事件处理 |
| 改动失控 | 单轮 diff 规模连续超限（每轮都在重写大文件=方向不稳） | 暂停 |

**人工类**
| 条件 | 含义 | 建议默认动作 |
|---|---|---|
| 人工叫停 | UI 随时 | 终止 |
| 里程碑门禁 | 达到预设中间指标后停下，人确认后再继续/终止 | 暂停 |

### [6] 评估、消融与确认
- **评测协议主权（D29）**：正式评分由产品侧**受保护的评测执行器**按冻结协议执行——数据版本与划分、主指标算法与方向、聚合方式、checkpoint 选择规则均在定稿时冻结；仓库内代码可改，但正式评分不依赖仓库内的评测实现；协议变更形成新实验版本并重建对照（转移规则见 D44）。测试集与训练数据隔离，测试评分只用于预先冻结的最终确认；查看测试结果后再改模型，须标记"测试集已参与开发"。**迭代期的验证评分同样由该执行器产出（R01）**——终止判定、跨轮比较与候选选择只使用可信来源指标（附带 run/数据版本/评测协议版本），D24 解析值仅作诊断。数据划分在协议冻结与基线验收前须通过**有效性校验（D43）**：按研究问题登记独立单位与分组/时间规则，校验跨集合对象交叉，需拟合的预处理仅在训练部分学习（例外协议单独声明）。
- **胜出方案选择（D37）**：进入 [6] 前锁定候选——按定稿时固定的规则（验证集主指标最佳轮 + 约束满足 + 平局规则）选出，**不依据测试分数换候选**；分别保存当前搜索版本、验证最佳候选与最终确认结果；"只有 BASE 可用""未改善""确认失败""证据不足"均为合法终态，生成如实报告；确认失败后如需再搜索，形成新实验版本而非暗中重开。
- 标准评估：按 experiment_plan 的评测命令在测试集执行。
- 消融实验（D36）：进入本阶段前基于**最终代码**重新校验消融矩阵（模块身份映射，结构演化后失效的矩阵项自动标记并重新生成）；**原矩阵仍然有效时自动进入确认；需修订时进入"待消融方案确认"暂停态，经用户确认后继续（R07，P5 显示该暂停原因）**。矩阵至少包含 BASE、完整方法与支撑核心主张的关键移除项；每项明确训练/推理干预方式、初始化、训练预算与 seed；不能运行的组合显式标注原因，不伪填结果。
- 多 seed 确认（D34，两门槛分阶段，R04 修订）：**候选多 seed 与 BASE 单 seed 的结果只用于预登记的初筛**（初筛指标、阈值与数据集在定稿时登记，判"值得补跑"）——初筛通过后补齐 BASE 与必要消融的同组 seed（默认 3，建议 3–5，可按项目配置，并行铺卡池）；**全部指定对照结果到齐后才作最终比较与结论，初筛结论可被推翻**；误差报告用均值±标准差（或置信区间）并注明样本数与随机源；初筛未过或证据不足时，如实报告"未通过预算内筛选/未完成充分确认"，不发布确定性优劣结论。**最终确认的判定标准在 plan 预登记（Q01）：主指标与方向、差异计算方式、最小关注改进、约束指标、误差/区间或检验方法——全部结果到齐仅表示实验完成，不自动等于提升成立**；区分"描述性数值改善"与"证据支持的主张"。本节条目为能力清单，**实际执行顺序固定为：验证集初筛 → 补齐指定训练与对照 → 冻结最终实验集合 → 测试集确认**（Q01）；采用其他预登记协议的项目须声明数据使用边界，仍受 D29 测试结果不回流开发的约束。
- **批实验完成标准（A07/D45）**：保存预期任务清单与逐项状态（全部完成/部分完成/失败/取消）；结果缺失显式显示，不补零、不静默剔除失败 seed；报告列计划/成功/失败数量及原因；恢复时只补未完成项（区分重传产物与重跑训练）。批实验绑定候选、协议、训练配方、初始化规则与矩阵版本；**确认期间不得通过模型修复悄悄改变候选（R06）**——方法或训练语义改变时生成新候选并作废受影响的已完成对照、按新清单重新确认；基础设施重试与产物重传可复用同一候选，不必全量重跑。

| D44 | 协议变更转移规则（复审 R05） | 协议类变更使受影响的基线/候选排序/消融结果失效并进入新对照验收；数据划分变化时检查继承权重的训练数据来源，必要时回合规初始化重训；控制类变更（预算等）不触发科研对照重跑 |
| D45 | 确认期方法一致性（复审 R06） | 批实验绑定候选+协议+训练配方+初始化规则+矩阵版本；确认期间方法/训练语义变化→生成新候选并作废受影响对照、按新清单重新确认；基础设施重试与产物重传可复用同一候选 |

## 5. 非功能需求

- **可复现性**：每 run 绑定 commit + 环境版本 + 配置 + 数据/划分版本 + seed + 初始化与预训练来源 + 实际执行命令 + 硬件与数值精度 + plan 版本（详见 [7]）。
- **审计**：LLM 每次分析、决策、改动全留档可回放。
- **安全兜底**（对 D6/D7 高自治组合的风险对冲）：紧急停止（远端确认制，D31）；GPU 时长预算为强制硬上限（D32）；LLM 修复重试上限；冒烟验证不过不入队；**运行时资产保护（D30）**——可写范围限项目运行目录、数据主副本只读、SSH/LLM 密钥与控制端数据库不可达，外来文本（论文/日志/仓库内容）不得成为控制面指令。
- **LLM 成本可见**：每项目 token 消耗统计（多供应商可配的前提）。
- **LLM 使用点清单**：① [3] 评审对话（方案初稿/反问清单/文献对照）；② [4] 每轮日志分析与改码；③ [4] 崩溃自修复（D23）；④ 报告与图表的标题/摘要等轻量生成。各使用点可分别配置供应商与模型（D11）。
- **断点恢复（D31）**：队列状态、轮次状态、产物索引全部持久化（本机数据库）；本机主服务重启后自动重连各服务器 agent，**先对账再调度**（识别已有 run 不重复派发、结果幂等入库），服务器端正在运行的训练不中断。

## 11. 关键验收场景（源自外部评审，验收 D29–D45 及相关正文）

| 场景 | 必须观察到的行为 | 对应 |
|---|---|---|
| LLM 篡改评测脚本（如得分×100），训练正常结束 | 正式评分口径不变；篡改不能计为模型提升，不能触发目标达成 | D29 |
| 仓库日志把验证分数打印成 0.99，可信评测为 0.80 | 搜索终止与候选排序使用 0.80；最终确认之前不误判成功 | R01/D29 |
| 生成代码试图写 BASE 原目录或数据主副本 | 被运行权限阻止；原资产内容不变；失败准确归类留档 | D30 |
| 服务器已启动训练但启动回执丢失，主服务随后重启 | 对账识别已有 run，不重复派发；结果只入库一次 | D31 |
| 预算用尽或用户点击取消 | 不再启动消融/多 seed/新一轮修复；失联时显示"停止待确认"，不虚报已停止 | D31/D32 |
| 剩余 1 GPU·小时，三卡并行申请任务，随后控制端离线 | 总授权不超余额（原子预留）；远端按约定额度/截止时间独立执行 | R02/D32 |
| 双 4090 并行消融，其中一项需要新依赖 | 两任务的代码/配置/环境各自匹配登记版本，互不覆盖 | D40 |
| 两台机器同路径的标签内容不同步 | 未通过校验的数据版本不可调度；不以"目录存在"放行训练 | D39 |
| 不同哈希的样本同属一个对象，跨训练/测试集合 | 对象级校验发现问题并阻断协议验收；文件校验通过不能放行 | R03/D43 |
| 第 8 轮最佳、第 12 轮终止，最终确认未超 BASE | 按预定规则选第 8 轮候选；如实报告确认未通过；不按测试分数换候选或换 seed | D34/D37 |
| BASE 单 seed 0.80、候选均值 0.81；补齐后 BASE 均值 0.82 | 初筛通过不提前发布确认成功；最终结论使用全部指定结果，允许反转 | R04/D34 |
| 定稿 A+B，最终演化为 C+B；消融 5 项挂 1 项 | 矩阵按最终结构重校验；失败项显式留空标注原因，不补零 | D36 |
| 修改划分后，旧候选权重曾训练过新测试集样本 | 按协议拒绝不合规继承；受影响对照重新验收，旧最佳不直接参与新协议排名 | R05/D44 |
| 训练进行中修改主指标或数据划分 | 旧 run 按其绑定版本追溯；新版本独立生效，结果不跨版本无提示合并 | D38 |
| 3 个 seed 任务加载同一训练完成的 checkpoint 只换推理 seed | 标注为重复推理，不作为独立训练的多 seed 证据；各任务初始化与累计训练量可追溯 | D35 |
| seed 1/2 用 commit X 成功，seed 3 修复方法后在 X' 成功 | 不输出混合版本的同方法三 seed 均值；按新候选清单重新确认或报告未完成 | R06/D45 |
| BASE 首轮报错，LLM 提议改损失函数重跑 | 区分环境兼容补丁与方法修改；修过的不再标"未改 BASE"；基线验收前不产出优越性结论 | D33 |
