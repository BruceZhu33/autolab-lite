## 1. 系统总体架构

```
┌────────────────────────── 用户控制机（mac/Win/Linux）──────────────────────────┐
│  ┌──────────────┐   进程内加载    ┌────────────────────────────────────────┐   │
│  │  Tauri 壳     │ ─────────────▶ │  Next.js 前端（static export）          │   │
│  │ (Rust, 窗口)  │                │  六模块工作台 · shadcn/ui · Monaco      │   │
│  └──────┬───────┘                └───────────────┬────────────────────────┘   │
│         │ spawn/监管（健康检查/单实例/优雅退出）      │ HTTP :7800 + WS 事件推送  │
│  ┌──────▼────────────────────────────────────────▼────────────────────────┐   │
│  │  sidecar（Python 3.12，FastAPI，SQLite WAL）                             │   │
│  │  ── 产品层：循环控制器(状态机) · 预算账本 · 评测执行器 · 数据版本同步      │   │
│  │  ── 引擎层：RD-Agent（自定义 Scenario/Workspace/Evaluator/Strategy）     │   │
│  │  ── LLM 薄客户端（OpenAI 兼容，按使用点配置）· paper-qa · matplotlib      │   │
│  └───────────────────────────────┬────────────────────────────────────────┘   │
└──────────────────────────────────┼─────────────────────────────────────────────┘
                        SSH 隧道（D14，加密+免防火墙）
                                   │  http://localhost:8900（每台服务器）
              ┌────────────────────┴────────────────────┐
              ▼                                         ▼
   ┌─────────────────────┐                  ┌─────────────────────┐
   │ gpu-agent @ 服务器A  │                  │ gpu-agent @ 服务器B  │
   │ Linux · 一卡一队列    │                  │ Linux · 一卡一队列   │
   │ A6000 ×1            │                  │ 4090 ×2             │
   └─────────────────────┘                  └─────────────────────┘
```

**职责铁律**：sidecar 是唯一决策点（编排/预算/判定/协议）；gpu-agent 只执行（收任务、跑进程、回日志、执行远端硬截止），不做任何科研决策。

## 2. 进程与生命周期

### 2.1 Tauri 壳 × sidecar（TD12）
- 壳启动 → 选空闲端口（7800 起）→ spawn sidecar → 轮询 `GET /healthz`（超时 30s 报启动失败）→ 加载前端。
- 单实例：壳持有文件锁；二次启动激活已有窗口。
- 退出：壳收到关闭 → `POST /shutdown` → sidecar 停止派发、对账在途任务、落盘 → 超时 10s 强杀；**不杀服务器上在跑训练**（D31，重启后恢复）。
- sidecar 打包：PyInstaller 单可执行文件，随 .app/.msi/.AppImage 分发。

### 2.2 前端 ↔ sidecar
- REST（`/api/*`）+ WebSocket `/ws/events`（轮次状态、GPU 占用、日志尾巴的事件流）。
- 所有长任务（环境搭建/同步/批跑）走任务句柄 + WS 进度，前端不阻塞。

### 2.3 sidecar ↔ gpu-agent
- 每台服务器建一条 SSH 隧道（asyncssh `forward_local_port`）→ 本地随机端口 → agent:8900。
- 断线重连后先 `GET /jobs?state=running` **对账再调度**（D31）。

## 3. 数据库 Schema（sidecar SQLite WAL，核心表）

```sql
servers(id, name, host, port, user, auth_json, status, last_seen)
gpus(server_id, gpu_index, model, vram_mb)               -- 注册时探测快照
projects(id, name, direction, base_source, repo_path, state, created_at)
project_gpus(project_id, server_id, gpu_index)            -- 卡池（D15）
plan_versions(id, project_id, ver, kind,                  -- kind: protocol|control（D38）
              yaml_json, created_at, note)
runs(id, project_id, round_no, role,                      -- role: round0|candidate|ablation|seed|baseline|eval
     plan_version_id, commit_sha, env_ver, data_ver,      -- ★四绑定（D40）
     seed, init_protocol, parent_run_id,                  -- 初始化协议（D35）
     status, gpu_job_ref, t_start, t_end, rc)
rounds(id, project_id, n, status, diff_summary, llm_analysis_json)
budget_ledger(id, project_id, entry_type,                 -- reserve|consume|release（Q02）
              gpu_h, run_id, created_at)
trusted_metrics(id, run_id, metric, value, eval_proto_ver, t_create)  -- 仅 D29 执行器可写
data_manifests(id, project_id, name, ver, files_sha_json, status)     -- D39
artifacts(id, run_id, kind, path, sha256, protected)      -- kind: ckpt|log|fig|report
papers(id, project_id, title, url, pdf_path, meta_json)
review_sessions(id, project_id, module, status, transcript_json)
llm_usage(id, project_id, use_point, provider, model, tok_in, tok_out, cost, t)
```

**预算账本原子性**：准入在单事务内 `INSERT reserve` 并校验 `Σconsume + Σactive_reserve ≤ B`，失败即拒；执行中消耗按心跳从 reserve 转 consume；结束/失效按 D31 对账释放。

## 4. gpu-agent 设计（服务器端，仅 Linux）

FastAPI + sqlite3，systemd 常驻 :8900。**一卡一队列、一任务一卡**（D15）。

```
GET  /healthz                       → {agent_ver, uptime}
GET  /gpus                          → [{index, model, vram_mb, mem_used, util, holder, external:bool}]
POST /jobs                          → 幂等（按 run_id 去重，重复提交返回已有 job）
     {run_id, command, env, workdir, mem_min_mb, deadline_at, budget_gpu_h}
GET  /jobs/{run_id}?tail=200        → {status, rc, log_tail, metrics_file}
POST /jobs/{run_id}/stop            → 终止进程组，回执确认制（未知=失联中，不虚报）
POST /jobs/{run_id}/checkpoint      → 记账心跳（实际消耗上报）
```

- 派发过滤：`mem_min_mb ≤ 卡空闲显存`（异构防护 D15/④）；区分平台任务与外部进程占用（A03）。
- **远端硬约束（R02）**：deadline_at / budget_gpu_h 由 agent 自行执行——控制端失联也到点即停。
- 每 job 独立进程组 + 日志落盘（`logs/{run_id}.log`）；指标文件由任务按契约写出。

## 5. RD-Agent 集成（引擎层）

四个自定义组件替换/包装（对应适配性评估结论）：

| 组件 | 实现 | 职责映射 |
|---|---|---|
| `AutoLabScenario(Scenario)` | 新写 | 提供领域描述/约束给 LLM prompt（含 plan 版本、冻结协议摘要） |
| `SSHWorkspace(Workspace)` | 新写 `execute()` | 快照同步（纯 Python SFTP+manifest）→ gpu-agent 派发 → 轮询回收 → 返回 Feedback 输入；复用其 ws_ckp 做回滚（D10） |
| `TrustedEvaluator(Evaluator)` | 新写 | **受保护评测执行器**（D29）：冻结的划分/指标算法/聚合在隔离快照内运行；唯一有权写 trusted_metrics 的模块；含 D43 划分有效性校验 |
| `BudgetedLoop` | 产品层包装 `evolve_iter` | 循环控制器（§6）：预算账本、终止判定器、plan 版本、断点恢复、D45 批实验身份绑定 |

## 6. 循环控制器状态机（sidecar 内，asyncio + SQLite 持久化）

```
IDLE ─▶ ENV_SETUP ─▶ REVIEW_GATE(D21) ─▶ ROUND0 ─┬─▶ 基线验收(D33)通过
                                                  ▼
   ┌──▶ PATCHING ─▶ SMOKE ─▶ QUEUED ─▶ TRAINING ─▶ ANALYZING ─┐
   │        │(失败: D23 自修复≤3)                              │
   │        ▼                                                  ▼
   │     REPAIRING                                    JUDGE（§5 判定器）
   │        │恢复                                            │
   └────────┴────────────────────────────────────────────────┘│未终止
                                                    ┌─────────┤
                                          继续(下一轮)│         │
                                                    ▼         ▼
                    EVALUATING ─▶ REPORTED    EXHAUSTED / CANCELLED / FAILED
                    （初筛→补齐→冻结→测试集，D34/Q01）   （同样出阶段报告 Q05）
   任意态 ─▶ PAUSED_*（预设暂停条件/矩阵修订确认/修订等待，D8 统一表述）
```

- 每次状态迁移落库；重启后从库里恢复状态并先与 gpu-agent 对账（D31）。
- ANALYZING 后、PATCHING 前插入 JUDGE；LLM 调用、冒烟、派发前三查：取消状态、预算、plan 版本（D32）。
- 批跑阶段（消融/多 seed）同一状态机内以 run 矩阵并行铺卡池，绑定候选+协议+配方+矩阵版本（D45）。

## 7. 其余自建模块要点

- **数据版本同步（D39/D16）**：默认纯 Python（SFTP + manifest sha256，临时目录→校验→原子 rename 发布）；检测到 rsync 时仅作传输加速。Windows 兼容（D48）。
- **运行隔离（D40）**：每 run 从仓库 commit 导出快照（git archive）+ 独占输出目录，运行期不可变，完成封存。
- **训练适配契约（A01）**：plan 的命令模板（omegaconf 渲染）+ 指标 schema/日志正则 + 退出码约定 + ckpt 路径，环境搭建末尾的冒烟按此验收。
- **图表/报告（D28/Q05）**：matplotlib 服务端出图 + 数据源文件；任何终态生成阶段报告，LLM 预算耗尽走确定性模板。

## 9. 打包与分发（D48 三平台）

CI 矩阵（GitHub Actions）：mac(.dmg) / win(.msi) / linux(.AppImage)。每平台两步：① PyInstaller 打 sidecar；② `next build（static export）` + `tauri build` 嵌入 sidecar 二进制。红线：全链路无平台专属 API（pathlib / 跨平台进程抽象）。

## 10. M1 纵切验收（技术口径）

单台 4090 服务器：注册→立项→远程建环境→手动触发一次训练→gpu-agent 队列/日志回收→sidecar 落库→前端曲线渲染。**M1 不含 LLM**；M2 起接 RD-Agent 闭环 + 单机可靠性验收（取消竞态/断线对账/预算执行/失败重试）。
