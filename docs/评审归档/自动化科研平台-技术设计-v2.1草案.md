## 1. 可信评测边界（T1 —— 三权限域 + 签名清单 + 测试结果不回流）

服务器上三个执行身份，评测资产由 **root/部署身份**拥有（0640，eval 进程只读，**任何执行身份不可写**）：

| 域 | Unix 用户 | 能看什么 | 跑什么 |
|---|---|---|---|
| train | autolab-train | 训练/验证数据、训练代码 | 训练循环（候选代码在此演化） |
| **candidate-infer** | autolab-infer | **仅测试输入**（无标签、无指标代码、无聚合规则） | 加载候选 checkpoint 做预测，输出 predictions 文件 |
| **trusted-aggregate** | autolab-agg | predictions + 测试标签 + 冻结指标代码 | 计算 trusted 指标；**永不加载候选 Python 代码**（只读产物） |

- 候选代码无论训练还是推理，都**接触不到标签与指标实现**——这是对 T1"eval 阶段跑候选代码"漏洞的根本封堵。
- gpu-agent 任务携带 **sidecar 签名的执行清单（HMAC）**：agent 校验签名+digest 才入队；agent 监听于 root 拥有的 Unix socket / 127.0.0.1:8900 并校验签名——训练用户无法伪造 profile 提交。
- **测试结果不回流（D29）**：`scope=test` 的指标为隔离数据面——不进入 LLM 上下文组装器、不进入 JUDGE 判定器、不参与候选选择排序、不出现在常规查询 API；仅 `GET /api/v1/projects/{id}/final-confirmation` 在批次冻结后可读，读取行为本身记审计。
- 部署要求：三用户初始化需 sudo（B1）→ 列为服务器注册前置条件；无 sudo 时降级模式（单用户 + 显式风险确认标记，可信边界弱化为约定级，UI 明示）。

## 2. 控制权与调用时序（S2 维持 + T6 修正）

RD-Agent 仅返回 {analysis, patch_diff}，副作用全部产品层显式提交（上轮 §2 时序不变）。**usage 计量修正**：由 gpu-agent 自采样并以事件上报（训练进程不可伪造、控制端断线仍独立计量）；sidecar 不再有 POST /usage 端点。

## 3. 数据模型修订（T3/T4/T5）

在 v2.0 基础上修正与补强：

- **FK 强绑定**：`runs.env_ver→environment_versions.id`、`runs.data_ver→data_versions.id`、`runs.recipe_id→training_recipes.id`（recipe 不可变，多 run 共享；删除 recipe→run 反向绑定）；`attempts.control_epoch` 与 `runs.control_epoch` 追加（排队任务按 epoch 归属）。
- **新增实体**：`initialization_specs(id, kind[from_scratch|parent_ckpt|pretrain], parent_attempt, ckpt_hash, load_report, optimizer_state_ref, cum_steps, seed_train, seed_infer)`——runs 引用之，替代自由字符串；`ablation_matrices(id, proto_id, frozen_json, status)` + `ablation_items(matrix_id, module_identity, config_json, run_id?)` + `modules(id, project_id, identity, code_refs)`（D36 落模）；`batches` 补 `init_spec_id`（五绑定齐）。
- **失效边泛化**：`invalidation_edges(cause_type[protocol|candidate|recipe|data_ver|method], cause_id, invalidated_kind, invalidated_id, reason, revalidate_status)`。
- **唯一性**：`evaluation_results UNIQUE(attempt_id, scope, metric, protocol_digest)`；`plan_protocols` 补 `parent_id, effective_round, status(frozen)`，不可变由仓储层禁止 UPDATE + trigger 双保险（B3）。
- **预算单权威（T4）**：上限只存 `budget_accounts.limit_s`；`control_state` 不再存预算（控制事件在同一事务更新账户并产出停止 outbox）。降预算冲突：`consumed+reserved > new_limit` 时按"预留大者优先释放"生成 STOP_REQUESTED；reservation→consume 用心跳累计量的**单调 delta**（乱序丢弃）；`expires_at` 到期不自动释放——须 D31 对账或硬截止确认后结算；`attempts.budget_reservation_id` 可空延迟回填，打破循环依赖。
- **对账 inbox（T5）**：agent 事件带 `{agent_instance_id, event_seq}`；sidecar 建 `agent_inbox UNIQUE(agent_instance_id, event_seq)` 与 `agent_cursors`；seq 缺口→报错→触发该 attempt 快照对账；agent 重装/seq 重置以 agent_instance_id 区分；重复 POST /attempts 幂等返回既有状态与结果摘要。

## 4. 状态机（T2 —— 正式迁移表）

格式：`from + event [guard] → to (+outbox)`。全表在实现仓库 `docs/state-machine.md` 维护，此处列骨架：

**项目层**：`INIT → ENV_SETUP → REVIEW_GATE[D21 确认] → BASELINE_ACCEPTANCE[D33 通过] → SEARCH → CONFIRMATION[批次冻结+测试确认] → FINISHING(reason) → REPORTING → REPORTED(outcome)`；`REPORTED` 为唯一终态（不可迁移/不可暂停）；`ACTIVE 系任意态 + pause 事件[D8 预设条件] → PAUSED(reason) [+resume|revise|terminate 事件回流]`；四 outcome ∈ completed|exhausted|cancelled|failed（FINISHING 携带）。
**run 层**：`PLANNED → PATCHING → SMOKE → QUEUED → TRAINING → EVAL_QUEUED → EVALUATING → METRIC_VALIDATING → ANALYZING → JUDGED`；分流域：`REPAIRING[进入：model 类失败且 retry<3；退出：冒烟过/超限→PAUSED_manual]`、`INFRA_RETRY[进入：infra 类且 retry<N；退出：换机重派/超限→PAUSED_manual]`、`METRIC_MISSING[D24 正式指标缺失，阻断直至人工/适配修复]`、`LLM_BACKOFF[指数退避，上限→PAUSED_manual]`。
**attempt 层**：`SUBMITTED → ACKED(agent 受理) → REMOTE_QUEUED(等待 GPU) → RUNNING → FINISHED|FAILED`；停止链 `STOP_REQUESTED → STOP_SENT → STOP_CONFIRMED`（失联停留 STOP_REQUESTED，可恢复）。

迁移执行：`UPDATE … WHERE state=? AND state_revision=?` CAS；每迁移附带 outbox 动作；副作用仅经 outbox 投递。

## 5. gpu-agent 契约修订

v2.0 §5 基础上：请求清单加 **HMAC 签名**（签名密钥随部署下发，仅 sidecar 与 agent 持有）；事件流统一 `{agent_instance_id, event_seq, payload}`；usage 为 agent 自采样事件；`GET /events?since_seq` 支持按 agent_instance_id 的游标。

## 6. sidecar API（T6 —— 澄清闸门语义）

capability token 覆盖**全部非 /healthz API 与 WS 握手**（B2，防只读泄露）。**闸门澄清**：OpenAPI v1 + 验收场景映射 + plan JSON Schema + WS 事件契约四件套是 **M1 的第一批工作包**（M1 内先行产出并评审，随后才写业务代码）；本文档 v2.1 的确认不阻塞 M1 启动，但阻塞 M1 内的编码阶段。
