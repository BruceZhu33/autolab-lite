## 二、建议补清的 5 项

### Q01｜“所有结果到齐”是完成条件，还不是“确认提升”的判定标准

**定位：第 63、124–129、176 行；D29/D34。建议在最终确认能力上线前补齐。**

本版已解决提前确认的问题，但只明确初筛指标、阈值和数据集需要登记，最终确认阶段尚未同样明确“满足什么条件，系统才输出哪一种结论”。例如最终均值只比 BASE 高 0.0001，而运行间波动较大，平台应输出“本次均值较高”，还是“提升已获支持”，不能由报告生成时的 LLM 自行决定。

建议在 plan 中补最终比较规则：主指标与方向、差异计算方式、项目关注的最小改进、约束指标，以及适用于该实验的误差/区间或检验方法。无需强制所有项目采用相同 seed 数、显著性阈值或统计检验；但应区分描述性的数值改善与证据支持的主张，条件不满足时允许输出“证据不足”。误差棒不等于方法间差异的判定规则；关于误差来源与计算方法的披露，可参照 [NeurIPS 官方 Checklist 第 7 项](https://neurips.cc/public/guides/PaperChecklist)。

同时建议把数据流写成明确默认顺序：**验证集初筛 → 补齐指定训练与对照 → 冻结最终实验集合 → 测试集确认**。第 126 行先列“测试集标准评估”，第 128 行才列初筛，目前是功能清单而不是执行顺序，不能仅凭条目顺序判断已有错误，但实现者需要一条准确的流程。若项目采用其他预登记协议，应明确其数据使用边界，仍受 D29 的测试结果不回流开发约束。

**最小补句**：“初筛默认使用验证集；最终确认前冻结指定实验集合，按 plan 中预登记的比较与证据规则判定结果，全部结果到齐仅表示实验完成，不自动等于提升成立。”

### Q02｜额度预留已要求，但“剩余额度”需要定义，避免重复扣减

**定位：第 88、174、261 行；D32。建议在预算实现前补齐。**

第 88 行写“所有活跃任务的授权总额 ≤ 项目剩余额度”，但“剩额”究竟是扣除已消耗后，还是再扣除预留后的可分配余额，没有定义。例如总预算 10 卡时，刚给任务预留 6 卡时，可分配余额变成 4；若用预留 6 ≤ 剩余 4 检查，就会错误拒绝本来合法的任务。这处歧义也来自上一轮我给出的简写，本轮将其明确化即可，不需要重做预算方案。

建议定义三个量：累计已消耗 C、活跃任务尚未消耗的预留 R、总预算 B。约束为 **C + R ≤ B**，可分配余额为 **B − C − R**。新任务原子增加 R；执行过程中把实际消耗从 R 转入 C；任务结束结算并释放未消耗预留。失联期间不能仅因控制端看不到任务就释放其仍有效的授权，释放条件须结合 D31 对账与远端截止规则。

**最小补句**：“项目可分配余额＝总预算−累计已消耗−活跃未消耗预留；新任务只从可分配余额申请授权，任务结束或授权失效后按对账规则结算释放。”

### Q03｜“消融确认是唯一人工介入点”与文档保留的暂停/修订流程不一致

**定位：第 63–64、68、76、85、96、121、127、150、163、293 行。**

消融确认本身已处理正确，问题是“唯一例外”说得过满。文档同时保留了修复三次失败等待人工、LLM 预算暂停、里程碑人工门禁，以及核心假设变化时的人工计划修订。D8 可以解释为正常自治受终止条件限制，但第 293 行直接写“全自动流程唯一例外人工点”，会让产品文案或状态机遗漏这些已有入口。

建议统一表述为：**“定稿后常规研究步骤自动执行；触发预设暂停条件、需要人工协议修订，或消融矩阵需要修订确认时等待用户。”** 该改动只准确描述已经存在的流程，不增加新的审批。

### Q04｜诊断指标缺失与正式评分缺失应分开处理

**定位：第 70、77、124、166 行；D24/D29/D41。**

本版已将仓库日志解析值降为诊断用途，但 D24 末尾仍泛称“指标不可得时不启动下一轮改码”。若可信验证分数完整，只是训练日志中的学习率或 loss 正则不再匹配，是否必须暂停整个研究？当前可能按旧规则停机，也可能继续，实现结果不一致。

建议将必需字段写入 plan：**正式决策指标缺失必须阻断；诊断字段缺失按必要性降级展示或进入诊断修复。** 某诊断字段若被启用的过拟合/健康判定器依赖，则按该判定器的缺失规则处理，不能把缺失当成满足条件，也不能默认绕过必要检查。日志缺失与可信评分失败应在 UI 中显示不同原因。

### Q05｜提前取消或耗尽预算时，应直接产出已有结果报告

**定位：第 86、131–134、170 行；D28/D32。**

D32 已正确阻止资源耗尽、用户取消、失败停止自动启动 [6] 的耗卡任务，但 D28 仍主要描述“[6] 评估完成后自动生成产物”。对 Round 3 就取消、没有进入 [6] 的项目，已有曲线、代码差异和终止原因是否能自动生成报告，缺少明确出口。

建议规定所有终态都能基于已归档数据生成阶段报告，列出终止原因、已完成/未完成实验、累计资源和当前可用候选。未执行的消融或多 seed 标为未完成，不伪造图表；不得为了补报告隐式启动训练。若停止原因是 LLM 预算耗尽，可使用确定性模板汇总，额外 LLM 调用仍受预算约束。这样既保留停止语义，也让失败或被取消的科研过程有可查看的产出。
